1   Pre-qualification

All four gates must pass before any data is collected or any Supabase row is created. If any gate fails, do not proceed — note the reason and revisit when conditions change.

  • AMVenue type — café, restaurant, or food and drink counter. Not retail, not services.
  • AMLocation — within walking distance of a rail or tube station, or a sports stadium.
  • AMOwner meeting completed — face-to-face or video call. Email alone is not sufficient.
  • AMLightning wallet — owner has, or is willing to set up, a Lightning wallet before handover. Required to receive payments. See Section 2 if they do not yet have one.
Notes

2   Data collection

Collect the following before opening Supabase. Confirm each item in writing (email or message) before the provisioning session.

Venue name As it should appear on the terminal and in all documents.
Trading address Full address for records. Used to verify map coordinates.
Owner contact email Magic link destination. Must be accessible on a phone or laptop at the venue.
Lightning address  (mandatory) venue_partners.lightning_address  —  confirm it resolves before provisioning.
On-chain address  (optional) venue_partners.onchain_address
Silent Payment address  (optional) venue_partners.silent_payment_address  —  BIP-352 format. Long string; confirm character by character if transcribed.
Mapbox coordinate note

Mapbox POI data has a known 10–20 m offset in dense City of London streets. Verify coordinates manually before seeding: use satellite view alongside a street-level check. Store corrected coordinates in coords_lat and coords_lng on venue_partners. Log mapbox_place_id if identifiable, for future automation.

If the owner does not yet have a Lightning wallet, recommend one of the following before the provisioning session. Record which app they use alongside the Lightning address — useful if they ever need to recover access.

Wallet Best for Notes
Phoenix Most owners

Self-custody. Automatic channel management. Clean UX. Recommended first choice.
Wallet of Satoshi Absolute beginners

Custodial — flag this explicitly. Zero friction. Suitable for initial setup; encourage a move to Phoenix once they are comfortable.
Zeus / Mutiny Technically confident

Self-custody, full control. Only recommend if the owner asks for it.
Rotating wallets

Because the Lightning address is stored in venue_partners.lightning_address rather than locked to an identity, the owner can switch wallets at any time. The procedure is: owner provides new Lightning address → R updates the column in Supabase → a new Venue Keys card is printed and handed over. Note this to the owner at handover so they understand it is possible.

3   Provisioning sequence

Order is mandatory

Steps 1 → 2 → 3 must be completed in this exact order. A merchant_users row cannot be inserted until the auth user exists in auth.users. Do not skip ahead and do not run steps in parallel.

  1. RInsert venue_partners row.

    Fields: name, address_line1, coords_lat, coords_lng, lightning_address, onchain_address (if provided), silent_payment_address (if provided), mapbox_place_id (if known), venue_type, active = false.

    Note the id (UUID) — needed in Step 3.

  2. RCreate auth user.

    Supabase dashboard → Authentication → Users → Invite user. Enter the owner’s contact email. Do not send the magic link at this stage — that happens at the handover meeting (Section 6).

    Note the user_id (UUID) from the newly created row — needed in Step 3.

  3. RInsert merchant_users row.

    Fields: user_id (from Step 2), venue_id (from Step 1), role = independent_owner or franchise_hq as appropriate.

  4. RSeed Staff PIN and Owner PIN.

    Choose PINs (or use owner’s preference if they have one). Seed both as bcrypt hashes (wf12) into merchant_users.staff_pin_bcrypt and merchant_users.owner_pin_bcrypt via the same seeding method used for Raj’s Steakhouse in CC-89.

    Record both plaintext PINs on a piece of paper to be written onto the Venue Keys card at the handover meeting. Do not store plaintext PINs digitally in any form.

  5. RVerify all rows.

    Read back: confirm venue_partners row exists with active = false. Confirm auth.users entry exists for the owner email. Confirm merchant_users row links the correct user_id and venue_id. Confirm staff_pin_bcrypt and owner_pin_bcrypt are not null.

    Do not proceed to Section 4 until all five checks pass.

Go-live switch

venue_partners.active is the go-live switch. It is set to false at provisioning and flipped to true only after the pre-flight test in Section 4 passes. There is currently no UI for this toggle — it requires a direct Supabase dashboard edit. R

4   Pre-flight: 21-sat test payment

Run this before the handover meeting. Confirms the payment rail reaches the merchant’s wallet end to end.

  1. RFrom the Refueler Blink wallet, send 21 sats manually to the merchant’s Lightning address.

  2. RConfirm the payment settled: check merchant_orders in Supabase — payment_status = ‘paid’ and status = ‘confirmed’.

  3. AMAsk the owner to confirm the 21 sats arrived in their Lightning wallet. Get written confirmation (message or email) before proceeding.

  4. RSet venue_partners.active = true in the Supabase dashboard. The venue is now live on the platform.

If the test fails

Do not proceed to the handover meeting. Diagnose and re-run. Common causes: incorrect Lightning address in venue_partners; owner’s wallet app has insufficient inbound liquidity (common with a brand-new Phoenix install — send a second small payment to open a channel, wait for confirmation, then re-test); Blink API key expired. Fix the root cause before flipping active.

5   Venue Keys card preparation

The Venue Keys card (merchant-venue-keys-v1.html) is the physical security document handed to the owner at the meeting. Fill it in by hand immediately before the handover — not days in advance.

  • AMPrint the Venue Keys card from Chrome. Update the venue name and date in the HTML before printing.
  • AMWrite Owner PIN in the Owner PIN field — by hand, in ink.
  • AMWrite Lightning address in the Lightning address field.
  • AMWrite On-chain address if provided.
  • AMWrite Silent Payment address if provided. Take care with character accuracy.
  • AMRecord the wallet app name on a separate line beside the Lightning address field (pen note in margin) so the owner has a reference if they need to recover access.
  • AMDo not type sensitive values into the HTML file. Do not photograph the completed card. Do not store a photograph of it on any device.
Staff PIN

The Staff PIN is not on the Venue Keys card — it is lower sensitivity and changes more often. Tell it to the owner verbally at the meeting and ask them to write it somewhere they control (the venue details box on the back page of the User Guide has a line for this).

6   Physical handover meeting

Work through this checklist in order at the venue. Allow 30–45 minutes.

  • AMTablet is charged. Connected to the venue’s Wi-Fi. Chrome is open, signed out, and showing the login screen at refueler.io/merchant/.
  • AMSend magic link to the owner email via the terminal login screen. Confirm they receive it within 60 seconds on their phone or laptop.
  • AMIf the magic link does not arrive within 60 seconds: check the owner’s spam folder first. If still absent: R resend via Supabase dashboard → Authentication → Users → find the owner email → Send magic link. Magic links expire after a short window — once resent, the owner must open it promptly.
  • AMOwner taps the magic link. Terminal opens to the Staff PIN gate. Confirm the venue name appears correctly.
  • AMWalk the owner through: Staff PIN entry → Queue view → OPS tab (venue status, pause orders, sign out) → Owner tab (owner PIN entry, venue name badge, revenue view).
  • AMNote: the terminal session lasts 12 hours. The owner will not be asked to sign in again during a normal operating day — only the Staff PIN is needed to start each shift.
  • AMConfirm the venue name loads correctly on first login. This is the confirmation that the terminal-displays-venue-name step is working.
  • AMBookmark refueler.io/merchant/ to the tablet home screen: Chrome menu → Add to Home Screen. The icon should appear on the tablet’s home screen before you leave.
  • AMHand over the User Guide (merchant-onboarding-v1.pdf) and the completed Venue Keys card (merchant-venue-keys-v1.pdf). Tell the Staff PIN verbally and ask the owner to write it in the User Guide’s venue details box now, in front of you.
  • AMRemind the owner: Venue Keys card stays in a safe or locked drawer, never on the counter. Never photographed. Not stored digitally.
  • AMConfirm Chrome is the browser in use on the terminal tablet. If the owner prefers a different browser: Chrome is required for the terminal tab only — everything else on the tablet is untouched. Safari adds its own headers and footers to printed documents and cannot be used for PDF output.
  • RNotify Rajesh (Signal or email) with venue name and confirmed go-live date and time.

7   Go-live checklist

Verify each item is confirmed before leaving the venue.

  • venue_partners.active = true — confirmed in Supabase before the meeting (Section 4, Step 4).
  • Pre-flight 21-sat test payment passed — owner confirmed receipt in their wallet.
  • Terminal loads correctly on Staff PIN entry.
  • Owner tab opens on correct Owner PIN.
  • Venue name displays correctly throughout.
  • Home screen bookmark saved in Chrome on the tablet.
  • Owner has physical copies of both documents: User Guide and Venue Keys card.
  • Staff PIN written in the User Guide’s venue details box.
  • Rajesh notified with venue name and go-live time.

8   Post-handover support

Support SLA: 2-hour response, Monday–Friday 07:00–18:00. Contact: support@refueler.io. Outside these hours: best effort; next business morning.

Session lifetime: 12 hours. Owners are not asked to sign in again during a normal operating day. If the session expires outside business hours, any staff member can email support and the terminal will be reopened on the next business morning.

Common issues:

Symptom First step Escalation
Magic link not received Check spam folder. Wait 60 seconds. R Resend via Supabase → Authentication → Users → [email] → Send magic link.
Staff PIN not accepted Confirm the correct PIN with the owner. Ensure Chrome (not Safari) is in use. R Verify staff_pin_bcrypt is not null in merchant_users. Reseed if necessary.
Queue is empty despite orders Check venue_partners.active is true. R Check merchant_orders RLS policies. Confirm venue_id join is correct.
Payments not appearing Confirm blink-webhook Edge Function is deployed and active. R Send a manual 21-sat test from the Blink wallet to the merchant’s Lightning address. Confirm payment_status = ‘paid’ in Supabase.
PIN reset requested Owner contacts support. Obtain new PIN preference. R Reseed staff_pin_bcrypt or owner_pin_bcrypt via server-side bcrypt. Print and deliver a new Venue Keys card if Owner PIN changed. Self-service PIN reset is not yet built.
Owner wants to change Lightning address Owner provides new Lightning address in writing. R Update venue_partners.lightning_address. Run a new 21-sat test to confirm. Print and deliver a new Venue Keys card.
